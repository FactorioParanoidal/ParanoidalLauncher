# Paranoidal Launcher

Лаунчер сборки Factorio **Paranoidal**: один exe, который ставит и обновляет моды сборки с GitHub, проверяет игру
и запускает её. Git, токены и настройки игроку не нужны.

**Скачать:** [Releases](../../releases) → `ParanoidalLauncher.exe`, прямая ссылка на последнюю версию:
https://github.com/FactorioParanoidal/paranoidal-launcher/releases/latest/download/ParanoidalLauncher.exe.
Положите его в папку Factorio 2.1 (2.1.24 или новее, с дополнением Space Age) и запустите. Если запустить из другого
места, лаунчер сам переедет в папку игры. Если Windows пишет «Windows защитила ваш компьютер», нажмите «Подробнее» →
«Выполнить в любом случае»: у exe нет цифровой подписи.

История изменений лежит в `CHANGELOG.md`. Агентам и разработчикам: начните с `AGENTS.md`.

## Что умеет

- Ставит и обновляет папку `mods` до ветки `pre_release_2.1` репозитория
  [FactorioParanoidal/ParanoidalModpack](https://github.com/FactorioParanoidal/ParanoidalModpack). Скачивается
  только разница.
- Проверяет игру: Factorio 2.1.24 или новее 2.1.x (точную версию называет zzzparanoidal сборки) с дополнениями
  space-age, quality, elevated-rails, recycler. Запускает её с `--mod-directory`.
- При запуске показывает окно выбора сборки: Paranoidal 2.1 или Paranoidal 2.1 Space Age (в активной разработке).
  Выбор можно запомнить. В главном окне сборки переключаются вкладками. У Space Age отдельный профиль со своими
  модами, сейвами и настройками.
- Работает только с Factorio 2.1. Если подходящей игры нет, объясняет, что нашёл и где взять Factorio 2.1 или
  дополнение Space Age.
- Папки, которые убрала или переименовала сама сборка, удаляет без вопросов. Спрашивает только про моды игрока.
- «Проверить файлы» побайтно сверяет всю сборку с GitHub и скачивает отличия.
- Узнаёт сборку, которая уже лежит в папке (скопирована, распакована, получена по сети), без интернета.
- «Откатить» и «Вернуть» делают шаг назад и вперёд без интернета. «Не менять версию» и «Версия хоста…» нужны,
  чтобы играть на той же версии, что хост.
- «Отчёт о проблеме» кладёт на рабочий стол ZIP для Discord.
- Обновляется сам: показывает все новые версии со списком изменений и советует обновиться.
- «Гайд» открывает иллюстрированный гайд по сборке, один HTML-файл рядом с лаунчером. Он обновляется вместе со
  сборкой.
- Переезжает в папку игры, если его запустили из другого места. «Ярлыки» создают ярлыки на рабочем столе и в меню
  «Пуск».
- Строка диагностики загрузки показывает, сколько грузилась игра и сработал ли кэш.
- Кнопка Discord ведёт на сервер сборки.
- Повторный запуск показывает окно уже открытого лаунчера поверх остальных.
- Интерфейс на русском и английском.
- Работает без интернета: играть, откатываться и делать отчёт можно и так.

<a id="versions"></a>
## Версии

- Версия задаётся в одном месте: `AppInfo.Version` в `src/AppInfo.cs`. Заголовок окна, журнал, `crash.txt`,
  `sync-log.txt`, версия exe и его манифест берут её оттуда. Больше нигде её не пишите.
- Любое изменение, после которого получается другой exe, требует новой версии (`x.y.Z` для исправлений и мелочей,
  `x.Y.0` для крупного) и нового раздела в начале `CHANGELOG.md` на русском.
- `build.ps1` следит за этим: `CHANGELOG.md` должен начинаться с `## <версия>`, а другой exe под уже собранной
  версией не соберётся. Сборка детерминированная: из одних исходников получается один и тот же exe. `-SameVersion`
  пересобирает текущую версию, пока её никому не отдали.
- Правка только комментариев или документов даёт тот же exe, новая версия для неё не нужна.

## Публикация

- Только по команде владельца. Сначала `powershell -ExecutionPolicy Bypass -File publish.ps1 -DryRun`: он делает всё,
  кроме тега, пуша и загрузки, и собирает в `obj\dryrun\`.
- `publish.ps1`: чистая `main`, не отстаёт от `origin` → тега `vX.Y.Z` ещё нет → `build.ps1` → самопроверка Harness →
  `tools\release-manifest.ps1` → аннотированный тег → пуш `main` и тега → `gh release create` (exe + `release.json`,
  заметки из раздела CHANGELOG, отметка latest) → проверка, что `releases/latest/download/release.json` отдаёт эту
  версию.
- Токен для `gh` берётся из Git Credential Manager (или `GH_TOKEN`) и не печатается.

## Где лаунчер ищет обновления

Всё задано в `AppInfo` (`Owner`, `RepoName`/`Branch`, `LauncherRepo`, `GuideRepo`, `ExeName`, `GuideFile`):

| Что | Где | Как |
|---|---|---|
| Сборка | `FactorioParanoidal/ParanoidalModpack`, ветка сборки: `pre_release_2.1`, у Space Age `pre_release_2.1_space_age` | git (папка `mods`) и REST API (список изменений) |
| Какая нужна игра | `raw.githubusercontent.com/…/<ветка или коммит>/mods/zzzparanoidal/info.json` | `factorio_version` и `base >= x.y.z` (`RemoteBuild`) |
| Сам лаунчер | Releases `FactorioParanoidal/paranoidal-launcher` | `releases/latest/download/release.json`, файл `ParanoidalLauncher.exe` |
| Гайд | Releases `FactorioParanoidal/guide-to-the-paranoidal` | `releases/latest/download/release.json`, файл `Guide_to_the_Paranoidal.html` |

- `release.json` (один формат для лаунчера и гайда): `schema` 1, `product` (`launcher`/`guide`), `version` x.y.z,
  `date`, `file`, `size`, `sha256`, `changes` (все разделы CHANGELOG, новые сверху: `version`, `date`, `text`).
  Лаунчер пишет его через `tools/release-manifest.ps1`, гайд через `tools/release.py` в своём репозитории (CI).
- Файл качается по тегу этой версии (`releases/download/vX.Y.Z/<файл>`), сверяются размер и SHA-256, и только потом
  он заменяет старый. Это обычные загрузки файлов, лимит запросов к API (60 в час) они не тратят.
- Сборка, лаунчер и гайд проверяются одновременно при каждой проверке обновлений (`Releases.CheckAll` рядом с
  `SyncEngine.CheckStatus`). Без интернета в журнал пишется строка, и ничего не блокируется.

## Самообновление (`src/SelfUpdate.cs`)

- Если есть версия новее, открывается окно со всеми версиями от установленной до новой и их изменениями, советом
  обновиться и кнопками «Обновить сейчас» / «Позже». Лаунчер спрашивает при каждом запуске (и по «Проверить
  обновления»), отказа «навсегда» нет. Пока идёт игра или операция, вопрос ждёт.
- Обновление: скачать в `ParanoidalLauncher.exe.new` → проверить SHA-256 и версию exe → запущенный exe
  переименовать в `.old` (перезаписать его нельзя, переименовать можно) → новый на его место → запустить с
  `--wait-pid <pid> --updated-from <версия>` → выйти. Новый процесс ждёт выхода старого (мьютекс), пишет
  «Лаунчер обновлён» и удаляет `.old`.
- Если папка только для чтения (Program Files), файл качается во временную папку, а замену делает этот же exe с
  правами администратора (`--install-exe <файл> <папка>`, UAC). Окно советует перенести папку игры в обычную папку.
- 1.1.0 и старше не умеют обновляться: им нужна ручная замена (анонс в Discord).

## Папка игры (`src/Relocation.cs`)

- Правильная работа гарантируется только из папки игры. При запуске (до распаковки MinGit) лаунчер находит игру:
  из настроек, если она подходит (Factorio 2.1 с дополнением Space Age), иначе поиском: рядом с собой, в Steam (все
  библиотеки), GOG и папках с «actorio» в имени в корне дисков, `\Games` и `Program Files`. Если подходящих установок
  несколько, он спрашивает, какую выбрать. «Не сейчас» оставляет лаунчер на месте с первой найденной игрой, а
  следующий запуск снова спрашивает (`settings.ini`: `pick-install=1`).
- Если лаунчер лежит в другом месте, он молча переезжает. Копирует exe как `ParanoidalLauncher.exe` (если там нет
  той же или более новой версии, иначе запускается та) и свою папку данных (без MinGit; пути в `settings.ini`
  абсолютные, новый exe делает их относительными), гайд, создаёт ярлык на рабочем столе, запускает копию с
  `--moved-from <старый exe>` и выходит. Копия удаляет со старого места только свой exe, `ParanoidalLauncher-data`
  (если там нет другого exe лаунчера) и копию гайда.
- Если не получилось (Program Files и др.), открывается окно: правильная работа гарантируется только из папки игры,
  «Перенести» просит права администратора, есть совет перенести игру в обычную папку. «Не сейчас» откладывает вопрос
  до следующего запуска. В режиме администратора данные идут в `%LOCALAPPDATA%\ParanoidalUpdater`.
- Лаунчер, который лежит в папке другой игры (Factorio 2.0.77: так будет у тех, кто играл на 2.0, когда их лаунчер
  обновится сам), переезжает так же. Его копия забывает пути и состояние прежней игры (`Relocation.ForOtherGame`:
  `factorio`, `mods`, `sa-root`, `pin`, `launch-build*`, `load-diag-key`), моды и сейвы прежней игры остаются на
  месте.
- Если подходящая игра не найдена, переезда нет: открывается окно «нет подходящей Factorio» (раздел «Сборки»), а
  «Выбрать папку игры…» в нём запускает переезд в выбранную папку.
- Переезд выключен, если задана `PARANOIDAL_LAUNCHER_NO_RELOCATE=1` или `PARANOIDAL_LAUNCHER_DATA_DIR` или рядом
  с exe лежит `build-info.txt` (папка сборки `dist`/`obj`).
- «Ярлыки»: рабочий стол (настоящий путь, с учётом OneDrive) и «Пуск» → `Paranoidal` (лаунчер и гайд), через
  `IShellLink`.

<a id="lines"></a>
## Сборки и окно выбора (`src/Lines.cs`, `src/StartScreen.cs`)

- Сборок две, игра у них одна: Paranoidal 2.1 (`pre_release_2.1`, линия `2.1`) и Paranoidal 2.1 Space Age
  (`pre_release_2.1_space_age`, линия `2.1-sa`, раздел ниже). Обеим нужна Factorio 2.1.x не ниже `base >= …` из
  zzzparanoidal установленной сборки, иначе последней на GitHub, иначе 2.1.24, и дополнения space-age, quality,
  elevated-rails, recycler (Quality, Elevated Rails и Recycler входят в покупку Space Age). Линия хранится в
  `settings.ini` (`line=2.1|2.1-sa`), ветку и правила знает exe.
- С 1.5.0 лаунчер не знает сборки 2.0 (решение владельца 2026-11-10). `line=2.0` от лаунчеров 1.3.0 и 1.4.0 при
  запуске становится `2.1`, «Не менять версию» сбрасывается (`MainForm.ForgetLine20`). Сборка для 2.0 в папке mods
  игры, которая уже стала 2.1 (Steam), обновляется до 2.1 обычным обновлением (статус «Нужно обновить сборку»), откат
  на неё не сохраняется. Сейвы 2.0 из другой папки лаунчер не переносит. Ветка `pre_release_2.0` нужна только
  лаунчерам 1.2.0 и 1.3.0, которым отказали в самообновлении.
- Запуск (решение владельца 2026-11-10, утверждено по макету): окно выбора сборки маленькое, с шапкой и полосой.
  - Сначала игра (раздел «Папка игры»): «Ищу Factorio…», при необходимости «Переношу лаунчер в папку игры».
  - Подходящей игры нет: окно «нет подходящей Factorio» с тем, что нашлось. Найдена 2.1 без дополнения: «Нужно
    дополнение Space Age»; найдена только старая игра (2.0.77 или 2.1 ниже нужной): «Нужна Factorio 2.1.24 или
    новее», где её взять (Steam: «Бета-версии» → «Нет»; GOG; factorio.com); ничего: «Factorio не найдена». Кнопки
    «Закрыть» (закрывает лаунчер, на диске ничего не меняется), «Выбрать папку игры…», «Проверить снова».
  - Игра есть: две карточки, каждая работает как кнопка. На карточке анимированный логотип, название, «основная
    сборка» или «в активной разработке», установлена ли сборка (версия zzzparanoidal) или сколько скачается. Внизу
    «Запомнить выбор» (по умолчанию выключено).
  - Выбор открывает главное окно этой сборки и проверяет её статус. Он ничего не скачивает, не копирует и не создаёт
    (решение владельца 2026-11-10): сборка ставится и обновляется только кнопкой «Установить»/«Обновить». То же при
    переключении вкладок.
  - MinGit распаковывается, пока игрок выбирает.
- «Запомнить выбор» пишет `ask-build=0`: при следующих запусках, если игра из настроек подходит, сразу открывается
  главное окно сборки из `line`. В главном окне справа от вкладок галочка «Спрашивать сборку при запуске» включает
  окно выбора обратно. Вкладки «Paranoidal 2.1» / «Paranoidal 2.1 Space Age» под шапкой переключают сборку, и `line`
  запоминает последнюю.
- Если новая версия сборки требует более новую игру, в журнале появляется строка, а перед обновлением вопрос.
- «Версия хоста…» с хостом на сборке для 2.0 (строка «Paranoidal 2.0, …», «Paranoidal, …» лаунчеров с 1.0.1 по 1.2.0 или
  zzzparanoidal его коммита) сборку не меняет: хосту нужно обновить игру до 2.1 и лаунчер.

<a id="space-age"></a>
## Space Age (`src/Profile.cs`, 1.5.0)

- Решения владельца (2026-11-10): Space Age выбирается в окне выбора при запуске или вкладкой «Paranoidal 2.1 Space
  Age» с пометкой «в активной разработке» (никогда «может ломаться»). Сборка берётся с ветки
  `pre_release_2.1_space_age`, линия `2.1-sa`, игра та же (2.1.x с теми же дополнениями).
- Профиль: папка `Paranoidal-SpaceAge` рядом с основной папкой mods (обычно в папке игры, поэтому скопированная
  целиком папка игры несёт и профиль). В ней `mods` и `.paranoidal-git` этой сборки, `config\config.ini`, сейвы,
  логи, кэш загрузки, `player-data.json`, чертежи. Путь хранится в `settings.ini` (`sa-root`, относительный внутри
  папки exe); если такой папки уже нет, профиль снова ищется рядом с папкой mods.
- Другое место профиля (решение владельца 2026-11-10): «Выбрать…» у папки модов на вкладке Space Age спрашивает
  папку, в которой будет лежать `Paranoidal-SpaceAge` (если выбрать саму папку профиля, берётся она), и переносит
  профиль целиком (`GameProfile.PlanMove`, `Move`). Окно «Перенести профиль Space Age?» показывает откуда, куда,
  размер, свободное место; на другом диске профиль копируется в `<куда>.partial`, переименовывается, и только потом
  удаляется старая папка, так что обрыв оставляет оригинал целым; на том же диске папка просто переименовывается. Если
  профиль уйдёт из папки игры, окно говорит, что при копировании игры на другой компьютер его нужно переносить
  отдельно. В выбранной папке уже есть профиль: вопрос «Использовать его?», ничего не переносится и не
  перезаписывается, прежний профиль остаётся на месте. Сборка ещё не установлена: лаунчер только запоминает место, и
  «Установить» ставит туда. Нельзя: внутрь самого профиля, в папку `mods` и папки с `.git`/`.paranoidal-git`, в папки
  без права записи (Program Files), на диск без места. Вернуть профиль в папку игры: «Выбрать…» и папка игры. Игра
  должна быть закрыта.
- Игра запускается с `--config <профиль>\config\config.ini --mod-directory <профиль>\mods`. Перед каждым запуском
  лаунчер пишет в этот `config.ini` секцию `[path]`: `read-data=__PATH__executable__/../../data` и
  `write-data=<профиль>` (абсолютный путь с прямыми слешами, как в рабочей конфигурации SA команды). Ключи кэша
  загрузки ставятся в него же. Остальной файл игра пишет сама.
- Пока профиля нет, вкладка Space Age показывает «Сборка ещё не установлена», зелёную «Установить», серую «Играть» и
  папку модов с пометкой «появится при установке». «Установить» показывает окно: где профиль, что копируется один раз (`config.ini` с `[path]` профиля,
  `mod-settings.dat`, `mod-list.json`, `player-data.json`, `blueprint-storage-2.dat`), галочка «Скопировать
  сейвы основной сборки» (по умолчанию выключена) с числом и размером, нужное место на диске (сборка + сейвы + ~1,3 ГБ
  на кэш) и свободное. Без места кнопка «Установить Space Age» неактивна. «Назад» ничего не меняет. Файлы, которые в
  профиле уже есть, не перезаписываются. После «Установить Space Age» главное окно показывает копирование и ставит
  сборку. Если установка прервалась, следующее «Установить» продолжает её с той же основой.
- Основа сборки: папки установленной сборки 2.1 копируются в профиль (`GameProfile.CreateSpaceAge`,
  `SyncEngine.Seeded`). Первая синхронизация заменяет отличающиеся файлы без вопроса «Файлы в папке mods», а папки
  основы, которых нет в сборке Space Age, удаляет без вопроса «Лишние моды». Если основа совпала с версией из
  истории ветки Space Age (её история включает 2.1), это обычное обновление с откатом. Проверено 2026-11-10: 2 771
  файл, 382 МБ вместо полной сборки.
- Каждая сборка обновляется только своей кнопкой «Обновить» на своей вкладке, переключение ничего не скачивает. В
  `mod-list.json` профиля включены space-age, quality, elevated-rails, recycler.
- Настройки сборки у профилей раздельные: `pin`, `launch-build`, `launch-build-prev`, `load-diag-key` у Space Age
  хранятся с суффиксом `-2.1-sa`, список изменений без связи в `commits-cache-2.1-sa.txt`. Диагностика загрузки и
  отчёт читают логи, `config.ini` и сейвы профиля.
- Сейвы 2.1 открываются в сборке Space Age, пока не запущена ракета (ПР-080 сборки). Сейв Space Age в обычной 2.1
  не откроется, это написано в подсказке вкладки «Paranoidal 2.1».
- «Скопировать версию» пишет «Paranoidal 2.1 Space Age, сборка от …». «Версия хоста…» различает линии по строке, а
  голый номер версии по ветке на GitHub (`GitHubApi.InBranch`: сначала `pre_release_2.1`, потом ветка Space Age) и
  подсказывает, какой вкладкой переключиться.

## Как выглядит окно (`src/Controls.cs`, `src/StartScreen.cs`)

- Окна похожи на окна Factorio (навык рабочей области `factorio-gui-design`). Цвета взяты из атласа интерфейса
  Factorio 2.1.24 (`data\core\graphics\gui-new.png`, позиции стилей из `style.lua`): рамка окна `#2D2C2D`, панели
  `#3E3D3E` с тёмной полосой подзаголовка, глубокие области списков `#1F1E1F`, текст заголовков `#FFE6C0`.
- Кнопки серые с чёрным текстом и оранжевой подсветкой под мышью. Зелёная кнопка означает следующее действие
  («Установить»/«Обновить», когда нужно обновиться, иначе «Играть»), красная удаляет. В диалогах «назад» слева,
  подтверждение справа, Enter подтверждает, Esc возвращает.
- Статусы показаны цветной точкой рядом с текстом, как состояние машин в игре, так что цвет никогда не стоит один.
  Подсказки тёмные, прогресс зелёный, пока идёт ожидание, по полосе бегает короткий отрезок.
- Отступы по сетке 4/8/12 пикселей, три размера текста. Шапка с логотипом и жёлто-чёрной полосой остаётся
  единственным особым элементом.
- Логотип (`LogoArt`): анимированный PARANOIDAL (`assets/paranoidal-logo.gif`, 900×123, 116 кадров, около 6 с на
  круг; в кадрах после первого только изменившиеся точки, поэтому файл весит 445 КБ вместо 13,6 МБ исходной гифки).
  У Space Age под ним плашка SPACE AGE из логотипа игры (`assets/space-age-plate.png`, вырезана из
  `data\space-age\graphics\entity\factorio-space-age-logo\factorio-space-age-logo-11tiles.png` Factorio 2.1.24).
  Один GIF на всё окно, анимация останавливается, пока окно свёрнуто или идёт игра. Скрипт, который их делает:
  `test-runs/launcher150-20261110/tools/make_logo.py` рабочей области.
- Вкладки сборок под шапкой: выбранная цвета панели с оранжевой полосой сверху, остальные серые кнопки.
- Окно выбора папки (`src/FolderPicker.cs`) системное, в стиле Проводника (`IFileOpenDialog` с `FOS_PICKFOLDERS`:
  адресная строка, панель слева, поиск, «Выбор папки»), а не старое «Обзор папок». Его цвета следуют теме Windows.
- Тексты окна пишутся простыми фразами без тире-связок, значков в начале строк и надписей заглавными буквами
  (1.5.0, по правилам humanizer, https://github.com/blader/humanizer).

## Гайд по сборке (`src/Guide.cs`)

- `Guide_to_the_Paranoidal.html` лежит рядом с exe (в папке игры), а если туда нельзя писать, в папке данных.
  Версия записана в `<meta name="guide-version">` в начале файла.
- Новая версия скачивается вместе с обновлением сборки. Если сборка свежая, а гайд нет, статус говорит «Вышла новая
  версия гайда», и «Обновить» качает только его. В журнале появляется выделенная строка «Обновился гайд по сборке
  Paranoidal». При «Не менять версию» гайд не обновляется.
- «Гайд» открывает только локальную копию, а если её нет, скачивает и открывает.

## Сборка и тесты

- `powershell -ExecutionPolicy Bypass -File build.ps1` → `dist\ParanoidalLauncher.exe` и `dist\build-info.txt`
  (версия и SHA-256). Нужны Roslyn `csc.exe` (Visual Studio или Build Tools) и reference assemblies .NET Framework 4.8.
  Пробная сборка, не трогающая `dist\`: `-Out obj/dev/ParanoidalLauncher.exe` (из bash с прямыми слешами).
- `tools\build-harness.ps1` → `obj\Harness.exe`, консольный прогон движка без окна (команды описаны в начале
  `tools\Harness.cs`): обновление, `--verify`, `--status`, `--rollback`, `--played`, `--info`, коммит как цель,
  `--loaddiag`, `--report`, `--parse-host`, `--parse-host-line`, `--paths`, `--releases`, `--guide`,
  `--download-launcher`, `--swap`, `--relocate`, `--cleanup-old`, `--shortcuts`, `--detect-all`, `--prepare-play`,
  `--line=2.1|2.1-sa`, `--other-game`, `--sa-move`, `--merge-config`, `--profile`.
  `--loaddiag-selftest tools\testdata\load-logs-2.0.77.zip` должен печатать `SELFTEST OK`.
- `tools\build-uishot.ps1` → `obj\UiShot.exe <папка> <ru|en> [папкаFactorio|-] [release.json]` рисует диалоги, окно
  выбора (карточки, три варианта «нет подходящей Factorio», ожидание) и главное окно обеих сборок в PNG через
  `PrintWindow`: окно за пределами экрана, без активации (фокус не отнимается).
  `tools\snap.ps1` снимает видимое окно.
- Переменные для тестов:
  - `PARANOIDAL_LAUNCHER_DATA_DIR`: своя папка данных лаунчера (настройки и моды игрока не трогаются);
  - `PARANOIDAL_LAUNCHER_TEST_OFFLINE=1`: git и GitHub ведут себя как без интернета;
  - `PARANOIDAL_LAUNCHER_TEST_GITHUB=http://127.0.0.1:<порт>`: релизы лаунчера и гайда с локального сервера
    (`python -m http.server` над папкой `FactorioParanoidal/<repo>/releases/...`);
  - `PARANOIDAL_LAUNCHER_TEST_SHORTCUTS=<папка>`: ярлыки туда, а не на рабочий стол;
  - `PARANOIDAL_LAUNCHER_TEST_AUTO=<файл>`: окно вне экрана без активации, ответ «да» на самообновление и первую
    установку Space Age, окно выбора отвечается само, «нет подходящей Factorio» закрывает лаунчер, журнал
    дописывается в файл, закрытие после проверки (сквозные тесты перезапуска);
  - `PARANOIDAL_LAUNCHER_TEST_PICK=21|sa`: ответ окна выбора в тестовом режиме (без неё сборка из `line`);
  - `PARANOIDAL_LAUNCHER_TEST_CHOOSE=none|<n>`: ответ на «несколько подходящих установок» (`none` означает «Не
    сейчас», без неё первая);
  - `PARANOIDAL_LAUNCHER_TEST_GAMES=<папка>;<папка>` или `-`: поиск игры видит только эти папки (и папку exe), а не
    Steam, GOG и `C:\Games`. Без неё тест, который ищет игру, может найти настоящие игры и перенести лаунчер к ним;
  - `PARANOIDAL_LAUNCHER_NO_RELOCATE=1`: без переезда в папку игры;
  - `PARANOIDAL_LAUNCHER_TEST_APPDATA=<папка>`: вместо `%APPDATA%\Factorio` (системная папка данных игры);
  - `PARANOIDAL_LAUNCHER_TEST_SWITCH=sa|21`: с `TEST_AUTO` одно переключение вкладки после первой проверки;
  - `PARANOIDAL_LAUNCHER_TEST_INSTALL=1`: с `TEST_AUTO` нажать «Установить»/«Обновить» после проверки (после
    `TEST_SWITCH`), окно Space Age отвечается «Установить Space Age» с копией сейвов, затем закрытие;
  - `PARANOIDAL_LAUNCHER_TEST_SA_FOLDER=<папка>`: с `TEST_AUTO` на вкладке Space Age «Выбрать…» папки модов с этой
    папкой (вопросы отвечаются «да»).
  В тестовом режиме диалоги не показываются (ответ «да», на «Лишние моды» ответ «Оставить»), второй запуск только
  отправляет сигнал. Точные копии версий сборки для стенда: `git archive <коммит> mods | tar -x -f -` из клона
  репозитория сборки.

## Где что лежит

- Данные лаунчера хранятся в `ParanoidalLauncher-data` рядом с exe (`AppInfo.DataDir`). Если туда писать нельзя или
  exe лежит в папке модов, они идут в `%LOCALAPPDATA%\ParanoidalUpdater`, причина пишется в журнал.
- `settings.ini`: `factorio`, `mods` (пути внутри папки exe хранятся относительными), `line` (последняя сборка),
  `ask-build` (`0`: окно выбора при запуске не показывается), `sa-root` (профиль Space Age), `game-cache`, `pin` («Не
  менять версию»), `lang`, `launch-build`, `launch-build-prev`, `load-diag-key`, `pick-install` (`1`: выбор установки
  отложен кнопкой «Не сейчас»). У Space Age `pin`, `launch-build`,
  `launch-build-prev` и `load-diag-key` с суффиксом `-2.1-sa`. `migrating` лаунчеров 1.3.0 и 1.4.0 очищается.
- Там же `sync-log.txt`, `crash.txt`, `commits-cache.txt` (список изменений для офлайна, у Space Age
  `commits-cache-2.1-sa.txt`), `load-diagnostics.txt`.
- Рядом с exe лежат `Guide_to_the_Paranoidal.html` (гайд), на время обновления `ParanoidalLauncher.exe.new`/`.old` и
  `*.download`; их лаунчер удаляет сам.

## Язык

- Строки пишутся парой на месте: `Tr.T("русский", "English")`.
- По умолчанию русский, если язык Windows или регион относится к одной из 15 постсоветских стран, иначе английский.
- Журнал, `sync-log.txt`, `crash.txt` и отчёт всегда на русском: их читает команда сборки.

## Как хранится папка модов

- `<папка>\mods` содержит рабочие файлы, `<папка>\.paranoidal-git` хранит лёгкий git: частичный неглубокий клон
  без содержимого файлов, sparse checkout только `/mods/`. Папку, рядом с которой лежит `.git` (репозиторий
  разработчика), лаунчер не трогает.
- Файлы сравниваются и пишутся побайтно (`info/attributes`: `* -text`). Factorio в мультиплеере сравнивает моды
  побайтно, и копия с концами строк CRLF дала бы «Содержимое мода отличается».
- Полная побайтовая проверка идёт при первой синхронизации, по «Проверить файлы» и если индекс пропал. В остальных
  случаях git доверяет размеру и времени файла.
- Отлаживая эту папку вручную, ставьте `GIT_NO_LAZY_FETCH=1`, иначе git начнёт качать сборку по файлу.
- Особенность git: в таком клоне `git reset <коммит>` читает объекты файлов, которых нет. Поэтому
  `SyncEngine.ResetIndex` при ошибке пересоздаёт индекс. `read-tree` не подходит: он теряет sparse checkout.
- Git никогда не трогает `mod-list.json`, `mod-settings.dat`, zip-моды и моды, которые игрок решил оставить.
  В `mod-list.json` лаунчер меняет только дополнения: quality и elevated-rails (у 2.1 ещё recycler) включены,
  space-age выключен; в профиле Space Age включены все четыре.
- Лишнее в `mods` (`SyncEngine.HandleExtras`): вопрос «Лишние моды» задаётся только про файлы игрока. Папки, которые
  убрала или переименовала сама сборка (есть в установленной версии, нет в новой), удаляет обновление без вопроса и
  сохраняет для отката. Папка с именем мода любой известной лаунчеру версии сборки (хвост прошлых обновлений,
  прежний ответ «Оставить») удаляется без вопроса; имена кэшируются в `.paranoidal-git\known-mods.txt`. Zip мода,
  который есть в сборке, удаляется, как и раньше.

## Распознавание сборки (`src/Recognize.cs`)

- Сама сборка ради этого не меняется: лаунчер не пишет в моды.
- Если версия неизвестна или файлы отличаются, лаунчер смотрит `mods\zzzparanoidal\info.json`. Сборка для
  Factorio 1.1 считается старой (Beta 8), про неё только предупреждение.
- Иначе лаунчер считает отпечаток папки в своём индексе `.paranoidal-git\fp-index` (в первый раз ~20 с на 950 МБ,
  потом только изменённые файлы) и сравнивает моды с версиями, которые уже знает.
- При точном совпадении версия принимается без скачивания, файлы не меняются. Иначе показываются ближайшая версия и
  отличающиеся моды.
- С интернетом подкачивается история за 120 дней (~2 МБ, ~20 с в первый раз), и сравнение повторяется.
- Особенность GitHub: из фильтров по деревьям он принимает только `tree:0`.
- Если первая установка идёт поверх неопознанной сборки, лаунчер спрашивает подтверждение и качает только отличия.
- Скопированная целиком папка игры опознаётся без интернета (проверено: 2 с).

## Без интернета

- Проверка GitHub делает одну попытку до 20 с. Без связи статус говорит «Нет связи с GitHub», «Играть» доступна,
  список изменений берётся из кэша.
- Обновление без связи сдаётся быстро. Без интернета работают «Проверить файлы» (пока файлы целы), откат, отчёт,
  диагностика, распознавание, правка `mod-list.json` и `config.ini`.

## Откат и «Не менять версию» (`src/Rollback.cs`)

- Перед обновлением лаунчер сохраняет в `.paranoidal-git\rollback\` только те файлы старой версии, которые
  меняются или удаляются, и список добавленных, а не всю сборку.
- Откат ведёт к версии, с которой игра последний раз запускалась (после двух обновлений подряд без игры тоже к ней).
  Он работает без интернета, и «Вернуть» возвращает обратно.
- «Не менять версию» отключает обновление. «Версия хоста…» принимает строку «Скопировать версию» хоста, переходит на
  его версию (качается разница) и включает «Не менять версию».

## Диагностика загрузки (`src/LoadDiag.cs`)

- После выхода из игры и при старте лаунчер читает `factorio-current.log` и `factorio-previous.log` и пишет одну
  строку: время до меню, сработали ли кэш данных и кэш атласа, и причину. Подробности есть в подсказке и журнале.
- Правила и строки лога описаны в `docs/factorio-load-cache.md`.

## Отчёт о проблеме (`src/Report.cs`)

- ZIP на рабочий стол, не больше 20 МБ (лимит Discord): версия и состояние, логи игры, `config.ini`,
  `mod-list.json`, `mod-settings.dat`, моды не из сборки, изменённые файлы сборки, журналы лаунчера, свежие дампы
  падений. По желанию сейв (последний, последнее автосохранение или выбранный), если влезает.
- `player-data.json` в отчёт не попадает никогда: там токен аккаунта Factorio. Имя пользователя в путях заменяется
  на `%USERPROFILE%` / `%USERNAME%`.

## Кэш загрузки игры (`src/GameConfig.cs`)

- Перед каждым запуском (галочка «Кэш загрузки игры», включена по умолчанию) лаунчер ставит `true` в
  `cache-prototype-data`, `cache-sprite-atlas` и `compress-sprite-atlas-cache` того `config.ini`, который игра читает
  сама (по `config-path.cfg`, иначе `%APPDATA%\Factorio`; у профиля Space Age его собственный).
- Меняются только эти ключи, остальной файл остаётся как был; копия до первой правки называется
  `config.ini.paranoidal-backup`. Пока игра запущена, файл не трогается (она перезаписывает его при выходе).
- Моды с зависимостью `~` не дают Factorio 2.0.77 и 2.1.24 использовать кэш данных, лаунчер предупреждает о них.
